# Aokkorn Backend

ระบบหลังบ้านสำหรับจัดการค่าใช้จ่ายทริปกับเพื่อน บันทึกว่าใครออกเงิน ใครร่วมจ่าย และใครต้องคืนเงินให้ใคร รองรับหลายสกุลเงิน ใช้ LINE Login และเก็บข้อมูลใน Supabase PostgreSQL

## แนวคิดการจัดโค้ด

แยกตามส่วนงานใน `src/api/` เช่น `trips`, `participants`, `expenses` และ `line-login` เพื่อให้แก้เรื่องหนึ่งแล้วตามโค้ดได้ภายในโฟลเดอร์นั้น แต่ละส่วนมี module ของตัวเอง แล้วนำมาประกอบเป็นแอปผ่าน `AppModule`

```text
main.ts                         เริ่มแอปด้วย AppModule
└── app.module.ts               ประกอบ modules ของแอป
    ├── LineLoginModule         เข้าสู่ระบบและ session
    ├── TripsModule             จัดการทริป
    ├── ParticipantsModule      จัดการผู้ร่วมทริป
    ├── ExpensesModule          จัดการค่าใช้จ่าย
    └── modules ส่วนงานอื่น
```

Module เป็นตัวประกอบ dependencies ตอนเริ่มแอป ไม่ใช่ตัวส่งต่อคำขอทุกครั้ง ส่วนงานที่ต้องใช้ความสามารถของอีกส่วนจะ import module นั้น และใช้เฉพาะสิ่งที่อีก module export ไว้

## แต่ละไฟล์ทำอะไร และทำไมถึงแยก

| ไฟล์             | หน้าที่ในโปรเจกต์นี้                                                                 | เหตุผลที่แยก                                                                                       |
| ---------------- | ------------------------------------------------------------------------------------ | -------------------------------------------------------------------------------------------------- |
| `.controller.ts` | รับ HTTP request ดึงข้อมูลที่ผ่านการตรวจแล้ว ส่งให้ service และคืน response          | แยกเรื่อง HTTP ออกจากการทำงานหลัก                                                                  |
| `.service.ts`    | ดำเนินงาน เช่น สร้างทริป บันทึกค่าใช้จ่าย หรือเริ่ม login โดยเรียกส่วนที่เกี่ยวข้อง  | อ่านลำดับการทำงานได้จุดเดียว และทดสอบโดยจำลอง database หรือ LINE ได้                               |
| `.module.ts`     | ลงทะเบียน controllers และ providers พร้อมระบุ imports/exports                        | ให้ Nest สร้างและส่ง dependencies ให้แต่ละ class โดยไม่ต้องสร้างเองทุกจุด                          |
| `.dto.ts`        | กำหนดรูปแบบข้อมูลเข้า/ออก ในโค้ดนี้มี parser และ Pipe สำหรับตรวจข้อมูลด้วย           | รวมกติกาของข้อมูลไว้ก่อนส่งต่อให้ service; TypeScript type อย่างเดียวไม่ได้ตรวจ request ตอนรันจริง |
| `.repository.ts` | รวม SQL การอ่าน/เขียน และงานฐานข้อมูลภายใน transaction                               | แก้ query ได้โดยไม่ปนกับ HTTP และจำลอง repository ตอนทดสอบ service ได้                             |
| `.cookies.ts`    | อ่าน ตั้ง และล้าง cookie ของ login/session                                           | รวมชื่อ อายุ และตัวเลือกความปลอดภัยของ cookie ให้ใช้ตรงกัน                                         |
| `.config.ts`     | อ่านและตรวจค่าตั้งต้น เช่น channel ID, callback URL และอายุ session                  | ตรวจค่าผิดตั้งแต่เริ่มแอป และไม่กระจายการอ่าน `.env` ไปทุกไฟล์                                     |
| `.guard.ts`      | `SessionGuard` ตรวจ session ก่อนเข้า controller และตรวจ CSRF สำหรับคำขอเปลี่ยนข้อมูล | ใช้การตรวจเข้าสู่ระบบร่วมกัน ไม่ต้องเขียนซ้ำทุก controller; การตรวจเจ้าของทริปยังทำในส่วนงานนั้น   |
| `.client.ts`     | ติดต่อบริการภายนอก เช่น LINE หรือ Lambda อัตราแลกเปลี่ยน                             | รวมรูปแบบคำขอและการจัดการคำตอบจากภายนอก และจำลองแทนได้ตอนทดสอบ                                     |

ชื่ออย่าง `.repository.ts`, `.cookies.ts` และ `.config.ts` เป็นวิธีจัดหน้าที่ที่เราเลือกใช้ ไม่ใช่ไฟล์ที่ Nest บังคับให้ทุกส่วนต้องมี เช่น ส่วนที่ไม่ใช้ cookie ก็ไม่ต้องมีไฟล์ cookies ของตัวเอง

## ตัวอย่างเมื่อสร้างทริป

```text
Request
  → SessionGuard: ตรวจ session และ CSRF
  → CreateTripPipe: ตรวจ body และแปลงเป็น CreateTripInput
  → TripsController.create: รับข้อมูลและเรียก service
  → TripsService.create: ส่งงานสร้างทริปให้ repository
  → TripsRepository.create: ตรวจโควตาและสกุลเงิน แล้วบันทึกทริป/เจ้าของ/วันแรกใน transaction
  → DatabaseService: ใช้ connection pool กลางติดต่อ PostgreSQL
  → คืน TripDetail กลับไปยังผู้เรียก
```

`TripsModule` ลงทะเบียน controller, service และ repository เหล่านี้ ส่วน `AppModule` import `TripsModule` เพื่อให้แอปใช้งานส่วนทริปได้

## อ่านและทดสอบอย่างไร

เริ่มจาก **controller → service → repository/client** เมื่อต้องรู้รูปแบบข้อมูลให้อ่าน DTO และเมื่อต้องรู้ว่าแต่ละ class เชื่อมกันอย่างไรให้อ่าน module

ฟังก์ชันตรวจข้อมูลและคำนวณ เช่น `parseCreateTrip` และการหารเงิน เป็น pure function: รับค่าแล้วคืนผลหรือข้อผิดพลาด โดยไม่ติดต่อภายนอก จึงทดสอบด้วย input/output ได้ตรง ๆ ส่วน service ที่เรียก repository, repository ที่ใช้ฐานข้อมูล, client ที่เรียก LINE และการตั้ง cookie มี I/O จึงต้องจำลอง dependencies หรือทดสอบการเชื่อมต่อแยกต่างหาก

เป้าหมายคือแยกตามเหตุผลที่ต้องแก้ไข ไม่ใช่เพิ่มไฟล์ให้ครบทุกชนิด งานเล็กควรอยู่แบบเรียบง่าย และแยกเพิ่มเมื่อมีหน้าที่ต่างกันชัดเจน
